Update ConditionLock so each checklist item, room item, vehicle item, document, equipment item, and custom entry uses a context-specific selection menu instead of the same generic status options everywhere.

Problem:
Currently many sections use the same cookie-cutter status options. This makes the app feel generic and less useful. A tire, fuel gauge, hotel bed, bathroom sink, cabinet hinge, receipt, rollaway bed, and business document should not all have the same status menu.

Goal:
Create item-specific condition/status menus based on the item type, category, and template context.

Keep multi-select status behavior:
- Users can select multiple relevant statuses when appropriate.
- Example: dirty + damaged.
- Example: present + stained + odor.
- Example: returned + damaged.
- Example: works + cosmetic damage.
- “Not applicable” and “Not checked” should remain exclusive statuses.

PART 4 — CUSTOM OPTION

Every item-specific menu should include:
- custom issue
- custom note

If user selects custom issue, show:
- custom issue title
- custom notes
- optional linked photos
- optional linked documents
- reported-to-company/receiver fields if relevant

PART 5 — BACKWARD COMPATIBILITY

Existing packets may already have generic statuses.

Keep them loading:
- If an old status exists, map it into statuses[].
- If old statuses do not exist in the new item-specific menu, show them under “Legacy / previous status.”
- Do not erase old data.
- Do not break old packets.

PART 6 — PDF / EXPORT / MANIFEST

Update exports to show item-specific statuses clearly.

PDF example:

Status: Low tread, Sidewall damage, Reported

PDF example:

Manifest/archive:
Include:

- statusOptionGroup

- legacyStatuses if any

Dispute summaries:
Use item-specific wording.

Example:
“Front passenger tire was marked low tread and sidewall damage at pickup.”

Example:
“Bed 1 was marked stained and odor and reported to the front desk.”

PART 8 — ACCEPTANCE CRITERIA

- The same generic status menu no longer appears everywhere.
- Tire/wheel items have tire/wheel-specific statuses.
- Vehicle exterior items have exterior damage statuses.
- Bathroom items have bathroom-specific statuses.
- Toilet tank/bowl/seat items have toilet-specific statuses.
- Bed/rollaway/crib items have sleeping-arrangement statuses.
- Documents/receipts have document-specific statuses.
- Signatures have signature-specific statuses.
- Business/commercial spaces have business-space statuses.
- Users can still multi-select statuses like dirty + damaged.
- Custom issue/custom note remains available everywhere.
- Old packets still load.
- PDFs and exports show the selected item-specific statuses.
- No backend, accounts, cloud sync, analytics, or server verification.
