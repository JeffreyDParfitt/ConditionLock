Build a mobile-first local-only web app called ProofPacket.

Goal:
ProofPacket helps people create timestamped proof-of-condition packets for rentals, stays, returns, handoffs, leases, claims, sales, as-is transfers, business changeovers, and disputes.

The app should guide users to photograph, inspect, test, open, close, lock, unlock, flip, lift, document, and export property condition before and after use or transfer.

The app should work for:
- Car rentals
- Hotel stays
- Airbnb / short-term rentals
- Apartment / home rentals
- Business / commercial leasing spaces
- Business changeovers
- Businesses being sold as-is
- Commercial spaces being transferred
- Offices
- Commercial kitchens
- Retail spaces
- Studios
- Salons
- Warehouses
- Workshops
- Moving trucks / storage units
- Equipment rentals
- Insurance claim documentation after an accident
- Property sales
- Home sales
- Vehicle sales
- Used car sales
- Boat / RV / motorcycle sales
- Equipment sales
- Furniture / appliance sales
- General as-is item sales
- Custom proof packets

Core positioning:
ProofPacket does not just tell users to take photos. It tells them what to open, close, lock, unlock, flip, lift, test, inspect, and document before someone blames them.

Tagline:
Prove the condition before there’s a dispute.

Secondary tagline:
Take the photos now. Avoid the argument later.

Additional positioning:
Document the condition before a rental, return, sale, handoff, lease, claim, or as-is transfer.

Privacy promise:
No account. No cloud. No server. Your proof packets stay on this device unless you export them.

Legal/usage disclaimer:
ProofPacket is an organization and documentation tool. It does not provide legal, insurance, medical, safety, code-compliance, inspection, appraisal, valuation, or professional advice.

Important constraints:
- No backend.
- No server database.
- No login.
- No accounts.
- No paid APIs.
- No cloud AI.
- No Firebase.
- No Supabase.
- No AWS backend.
- No external backend services.
- No required internet connection after loading.
- Do not upload photos anywhere.
- Store all user data locally on the device/browser.
- Prefer IndexedDB for proof packet data and photo storage.
- Use localStorage only for lightweight settings if needed.
- The app should be PWA-style and mobile-first.
- Use React, TypeScript, and Tailwind CSS.
- Use clean, readable, well-organized code.
- Use client-side PDF generation.
- All proof packets, photos, notes, checklists, signatures, and exports should remain local unless the user manually exports them.

Tech stack:
- React
- TypeScript
- Tailwind CSS
- IndexedDB, preferably through Dexie if available
- Client-side PDF generation using jsPDF or another browser-compatible PDF library
- Optional: client-side ZIP export if easy, but PDF export is the priority
- Optional: PWA manifest and offline support if easy

App name:
ProofPacket

Main user flow:
1. User opens app.
2. User taps “Create New Proof Packet.”
3. User chooses a packet type.
4. App creates a guided checklist based on the packet type.
5. User adds photos, notes, statuses, dates, and reference details.
6. User can document “Before,” “After,” “At Pickup,” “At Return,” “At Sale,” or “At Transfer” condition depending on packet type.
7. User can add more checklist items at any time without restarting.
8. User can add communication logs.
9. User can capture acknowledgment signatures.
10. User can export a clean PDF report.
11. User can back up/export local data manually.
